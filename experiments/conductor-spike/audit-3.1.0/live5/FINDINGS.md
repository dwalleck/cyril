## Method notes

- **No cyril log level.** `crates/cyril/src/main.rs` installs `tracing_subscriber::fmt()` without an env filter; `cyril.log` is INFO only and never shows frames. The stdio tap (`live5/tmp/node-tee.sh` as `KIRO_AGENT_PATH`: `exec > >(tee -a …a2c)`, `exec < <(tee -a …c2a)`, `exec node "$@"`) gives a complete, line-accurate capture of both directions while keeping node as cyril's direct child (verified with `pgrep`: cyril → node, the two `tee`s hang off node). It costs nothing to a scenario and should become the standard cyril-on-KAS method (the brief's `RUST_LOG=debug` cannot work). Trap for the next lane: the tap captures the **access token** in the `getAccessToken` reply — redact `"accessToken":"…"` before leaving the files in the tree (done here after every scenario).
- **Count `"result":{"stopReason"`, not `"stopReason"`** — `turn_completion` info frames also carry the key; my first wait fired a turn early (recovered by re-reading the screen).
- **Waiting without `sleep` in the foreground:** `until … ; do sleep 0.5; done` loops ran fine as `run_in_background` one-shots (and short ones in the foreground); the pending-condition pattern "turn result OR `request_permission` OR `_kiro/mcp/elicitation`" avoided every hang on an unexpected approval overlay.
- **hex1b** behaved exactly as the live lane described: `send_terminal_input` + `send_terminal_key Enter`, `Escape` closes overlays, `Down`/`Enter` pick options, `s` cycles scope; `wait_for_terminal_text` needs a string not already on screen (I used the overlay titles and ids). `/quit` works and is the clean way to end a scenario — Ctrl+C/Ctrl+Q were not needed. The terminal inherits the user's `SHELL=/bin/fish`, which is what made the V2 result differ from every probe (trap 34 made real).
- **Trap 34 in practice:** the only reason the "unparseable command auto-deny" expectation failed is that every probe answers `shell_type: bash`; cyril answers the user's shell. Any host-callback verdict must be re-read from cyril's own reply (`<S>.c2a.jsonl`, the `shellType` result) — done for every scenario here (`fish` throughout).
- **`/usage` is a ledger, not a session view** — a discriminator (`/new` + `/usage`, then a fresh process + `/load` + `/usage`) was needed to see it; without the second process the V5 numbers would have been misread as "the replayed turn sum".
- Seeds reused from the live lane (`live/tmp/cyril-S*-*`) with only the fixture log paths re-pointed into `live5/`, the S8 hook files added, and git commits added so `git stash list` had a repository; the V3 seed is new under `live5/tmp/`. The S7 workspace now contains the helper-created `kh/` dir (left as evidence).
