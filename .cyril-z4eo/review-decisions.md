| 2 | Generic workspace compilation is not a distinct placement fence | DesignFalsifier | Design | Yes. | 3 | Historical findings cite the now-evolved probe/oracle as if they still reproduce the pre-fix output | StandardsReview | Evidence/design | Yes. `findings.md:9-35` names the live paths, while HEAD's oracle requires `VecDeque` and emits five fixed-state lines. | Modify | Pin the historical evidence to immutable prototype commit `955a1a3`; keep HEAD's oracle as the checkpointed-build oracle instead of duplicating executable artifacts. |
| 4 | Main-session approval titles allocate on every frame | StandardsReview | Hard convention | Yes. | 5 | Approved queue-boundary negative compile fence is absent | SpecReview | Spec | Yes. | 6 | Approval attribution compares a display label with a domain id | StandardsReview | Design / latent bug | Yes. `render.rs` compares `TuiState::session_label()` with `ApprovalState::session_id`; the values agree only because the sole production label writer currently copies the raw id. | Modify | Add typed `TuiState::main_session_id()` state and compare `SessionId` values. | 7 | Empty-origin display mapping is duplicated and an empty id was called unreachable | StandardsReview + aggregator | Duplicated code / invalid-input hardening | Partly. | 8 | Option and trust approval phases duplicate modal-title construction | StandardsReview | Duplicated code | Yes. `widgets/approval.rs` repeats the same match/style shape for two base titles. | Accept | Extract one file-private title helper while preserving borrowed static titles for unattributed approvals. |
| 9 | The queue-privacy compile fence is misplaced on `TuiState::approval` | StandardsReview | Judgment call | No actionable defect. The E0616 and E0507 doctests jointly fence the approved read-only seam, require a public rustdoc anchor, and run together in existing doctest gates. | Reject | Keep both halves co-located on the seam they constrain; moving only E0616 would scatter one boundary claim without improving behavior or diagnostics. |
| 10 | `(SessionId, TrustOption)` should become a named trust-grant type | StandardsReview | Style | No actionable defect. It is a single producer/consumer pair, immediately destructured, and matches existing paired-result APIs such as `picker_confirm() -> Option<(String, String)>`. | Reject | A public type would add interface weight without eliminating repetition or an illegal state. |
| 11 | Queued approvals have no depth cue and a promoted head can be confirmed before it is drawn | SpecReview + aggregator | Reviewer-added UX / real input-safety bug | Partly. The blind-confirm bug is real: `App::run` drains buffered terminal events before redraw while approval resolution synchronously promotes the next head. | Modify | Do not add unapproved queue-count UI. Treat an approval as an input-batch boundary so the outer loop redraws before any buffered event can act on a promoted request. No tracker deferral remains because the actual hazard is absorbed here. |
| 12 | Design-named trust/terminal regression fences were folded into one stress test | SpecReview | Spec traceability | Yes in naming, not coverage. | 15 | Queue-boundary compile-fail doctests are scope creep | SpecReview | Scope | No. They are the executable fence for approved design claim 8 and run in the repository's existing doctest gates. | Reject | Keep both compile-fail fences. |
