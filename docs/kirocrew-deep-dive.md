# KiroCrew deep dive — lessons and features for cyril

**Date:** 2026-08-04 · **Source:** `github.com/kirodotdev/kirocrew` @ `e44259ce` (local clone `~/repos/KiroCrew`)
**Method:** 11-agent survey (9 domain readers → synthesis + adversarial critic), 87 raw findings, 8 evidence spot-checks (7 VERIFIED, 1 REFUTED). Companion artifacts: memory `reference_kirocrew_platform`, filed issues `cyril-rtrh` (session/load resume) and `cyril-2yn8` (`_meta.kiro` tool identity).

KiroCrew is AWS's open-source agent-orchestration gateway. It matters to cyril for one structural reason: **it is a sibling implementation of cyril's bridge** — a production ACP client driving `kiro-cli acp` (v2 engine, `_kiro.dev/*` dialect) plus `claude-agent-acp`, hardened by a 39k-user internal deployment. Its ACP layer is a catalog of wire scars; its product layer is a preview of cyril's proxy-stage roadmap, built by someone else first.

## Top adoptions (value ÷ cost)

1. **Security-filter interrupt auto-complete** — kiro emits the exact chunk `"Tool uses were interrupted, waiting for the next user prompt"` then **never sends the `session/prompt` response**. cyril's bridge maps that response to `TurnCompleted`, so this wedges `is_busy` forever *today*. Exact-after-strip marker match in `convert/kiro.rs`, synthesize `TurnCompleted`, keep the chunk visible. Confirm first with `KIRO_ACP_RECORD_PATH` + a credential-keyword bash prompt. **S.**
2. **Unknown-`sessionUpdate` hardening (K1 prerequisite)** — `steering_queued/consumed/cleared` (since 2.9) and `usage_update` ride the **standard** `session/update` method; the pinned crate's `SessionUpdate` enum has no catch-all, so the first steer receipt after K1 ships would hard-fail deserialization. Verify how acp 0.10.2 actually fails, then pre-filter raw frames to the ext path. Nothing breaks *today* (cyril never sends `_session/steer` yet) — but K1 cannot ship without this. **S–M.**
3. **Cancel-ack grace window; later, cancel-as-probe** — Esc-cancel is fire-and-forget today; an unacked cancel leaves UI state undefined. Add a ~10s grace for the stopReason, synthesize a terminal notification if unacked (extends the "bridge MUST notify for every command" invariant). The same mechanism later doubles as a zero-risk staleness probe (ack ⇒ turn was live; no ack ⇒ confirmed wedge). Classify kiro's "already in progress" error text into a typed `PromptBusy`. **M.**
4. **Cancelled-turn context-restore preamble** — kiro does not persist cancelled turns; after Esc the model has amnesia about the half-answered ask. cyril already holds the prompt + partial `streaming_text` in UiState — stash on cancel, prepend a capped `[PREVIOUS TURN WAS CANCELLED]` preamble on the next SendPrompt. Every Esc today silently lobotomizes the next turn. **M.**
5. **Vendor capability profile** — KiroCrew's two-backend scar tissue says the provider abstraction leaks at exactly five seams: slash-command transport, config/effort mechanism, compaction signaling, multiplexing eligibility, resume/sid namespaces. Encode as typed capabilities on an `AgentProfile` before the second vendor, not after. (The per-field handshake divergence table from their docs is *not* trustworthy — see REFUTED above; rebuild it from captures when the claude-agent-acp track starts.) **S now.**
6. **Trusted tool identity + permission-time join** *(extends `cyril-2yn8`)* — `session/request_permission` is identity-poor (no kind, no `_meta`, truncated title): cache rawInput/identity per `toolCallId` at the ToolCall notification and join at permission time; show the real command in the approval overlay, never the LLM-authored title; fail closed when identity is absent.
7. **`session/new` mcpServers injection precedence — the stage enabler** — session-injected servers *override* same-named agent-spec entries; the spec's copy never launches. Per-session MCP substitution is therefore a pure protocol operation: a cyril stage (skills, memory, audit) splices its own MCP server into every session with zero writes to user kiro config. Undocumented; pin with a live test per release. **This single fact de-risks the whole proxy-stage architecture.**
8. **Directive-driven fake ACP agent** — a standalone stdio binary speaking real ACP with prompt directives (`[[TOOL]]`, `[[GATED]]`, `[[SLOW_NOACK]]` cancel-deaf, `[[ERROR]]`). cyril's only offline backend is `KIRO_MOCK_CHAT_RESPONSE` (strings only); cancel-deaf and permission paths are untestable today. Doubles as the vendor-neutral track's test substrate. **M, huge leverage.**
9. **`session/load` resume recipe** *(extends `cyril-rtrh`)* — activity-based response deadline (the **entire transcript replays as notifications before the response**; reset per frame, 600s cap); stale-lock refusal ("active in another process") gets a bounded backoff ladder before falling back to `session/new`; drain turns before SIGTERM so the lock releases.
10. **docs-lint + gate-ID'd invariants** — ~200-line stdlib CI linter: no dangling doc links, no phantom spec paths cited from code/CLAUDE.md. cyril has 40+ `docs/kiro-*.md` and a citation-dense CLAUDE.md with nothing checking them. Pair with stable IDs on prose invariants, each pinned by a named test. **S, cheapest high-leverage item.**

## Bigger bets (plan, don't sprint) — with portability caveats

- **Liveness oracle / watchdog.** Verdicts WORKING/DEAD/STUCK_INPUT/UNKNOWN with evidence; timeouts govern *only* UNKNOWN; probe errors degrade to UNKNOWN, never a kill. Critic's caveats: the evidence engine is 100% Linux `/proc` (no Windows/macOS analog; unreachable across the WSL boundary from native-Windows cyril); sampling is blocking I/O that must not run on the `!Send` bridge thread; and in a TUI the human *is* the main session's watchdog — the real consumer is unattended workflow peers. Adopt the **taxonomy and policy** now (item 3 is the first slice); the /proc engine is Linux-only phase 2.
- **N-session multiplexing.** Production existence proof for the session-level workflow decision: one process, single-reader demux, skip-don't-crash, drop-don't-broadcast, staged early OAuth notifications (they can arrive tagged with the new sessionId *before* `session/new` returns), recovery = per-session cancel never process kill; warm reuse cuts ~3–5s/400MB per peer to ~200ms. Critic's caveat: their invariants are proven on **unbounded** asyncio queues; translated to cyril's bounded mpsc, "broadcast no-sessionId frames to all queues" is cross-session head-of-line blocking — the exact bug class cyril-g9vt just fixed. Backpressure design is ours to do.
- **Workflow-engine checkpoint cluster.** Durable per-step checkpoint at settle time; resume = deterministic prefix replay; edited workflow drops the cache; outcome as `enum {Stopped, Failed, Completed}` (user-stop is neither success nor failure); typed budgets per failure class; **never replay a prompt after any activity was observed** (a mutating tool may have run pre-first-token — continue-nudge only); unattended peers need a wall-clock bound + deny-by-default exact-match allowlist or they wedge on a permission prompt nobody answers.
- **First-prompt injection architecture (the stage spec, essentially complete).** `[AGENT SYSTEM PROMPT]` + session-context block once per session; light per-turn prepends; user text last with exact byte-span bookkeeping; authority via framing + structural-marker neutralization of persisted content; window-share (not absolute-char) budgets; write-time XPIA screening with audited blocks.

## Do not copy

- **Silently-lying provider defaults** (no-op `compact()`, optimistic `'acked'` cancel) — capability-gate at compile time or return an explicit `Unsupported` variant. Direct Option-over-sentinels violation.
- **Advisory capability manifests** — App-Kit declares permissions it mostly doesn't enforce. Stage manifests must gate by construction or omit the field.
- **In-memory orchestration position / parallel pause bools** — persist workflow *position* from day one; one pause enum.
- **Resume keyed on display strings** — their TASK.md runner regex-parses its own progress report as the checkpoint; derive the view from typed state, never parse the view back.
- **Pattern-matching as the security boundary** — even their deep deny engine self-describes as not-a-boundary; hard guarantees rest on model-uninfluenceable ground (resolved paths, trusted `_meta`). Also: displayed counts derived from prose drift (their rule counts disagree across four docs).
- **Ratchet baselines** (`--max-warnings 1116`, disabled-but-documented formatters) — cyril's zero-warning posture is the counterfactual; keep it.
- **Structural constraint to respect:** permission enforcement *only* at `request_permission` is incomplete — `allowedTools` (which cyril itself writes via `kiro_agent_config.rs`) suppresses permission requests entirely. A policy stage must also intersect at config-write time and watch tool_call notifications as a detection tier. Corollary (critic): for the v2 engine cyril **cannot** enforce by interposition on fs/terminal traffic — v2 never calls ACP fs/terminal callbacks; enforcement-by-interposition needs KAS or spawn-path sandboxing.

## Addendum: Knowledge Library (post-survey read, 2026-08-04)

The survey missed `knowledge/` (5.9k lines; the memory-learning reader had it in scope but returned nothing). Read directly afterward — it's a name collision, not the same feature as kiro-cli's knowledge:

- **kiro-cli's knowledge** (our catalog): agent-side knowledge bases, indexed by kiro itself, retrieved pull-based via the built-in `knowledge` tool. Opaque to the client.
- **KiroCrew's Knowledge Library** (`docs/system-specs/modules/knowledge.md`): a fully client-side personal knowledge graph. SQLite store (items + FTS5 + entity/relation graph), local Ollama embeddings (`qwen3-embedding:0.6b`), hybrid retrieval = FTS5 + graph traversal + vector fused with RRF (vector leg weight 2.0). Ingests folders/uploads/artifacts/URLs with change watchers, cross-source dedup, sensitive-path refusal before any read, and sig-gated self-heal re-embed. Served to the model as the `local_knowledge_search` MCP tool on the built-in `kirocrew-core` server — i.e., delivered through the same mcpServers session-injection mechanism as everything else. The two coexist in a session: the model can see both kiro's `knowledge` tool and `local_knowledge_search`.

**The standout pattern the survey missed — LLMPool** (`knowledge/llm_pool.py`): entity extraction and URL fetch run on a bounded pool (default 3) of **long-lived ACP worker sessions** driving a dedicated, auto-installed `kirocrew-knowledge` kiro-cli agent pinned to the cheapest model (claude-haiku-4.5), with idle scale-to-zero after 300s (frees ~1GB of process trees) and PID shielding against the gateway's orphan sweep. They also auto-install `kirocrew-research` and `kirocrew-heartbeat` sibling agents. The architectural idea for cyril: **ACP as the universal LLM API for the client's own features** — a memory/audit/summarization stage can acquire a pooled cheap-model agent session over plain ACP instead of needing its own API keys or SDK. This slots directly into the proxy-stage roadmap and was absent from the top-10 only because no reader surfaced it.

### Addendum: self-authoring skills (post-survey read, 2026-08-04)

The survey covered skill *loading* but missed the authoring loop (`skills.py` §auto, `history.py` `_process_auto_skills`, `skills_script_validator.py`). During the 3h-idle consolidation pass, an LLM mines conversation history for repeated multi-step procedures (≥5 tool calls, 0.85 similarity dedup vs live + pending skills, judge-model arbitration) and drafts a complete `SKILL.md` (frontmatter `source: auto`) plus optional Python helper scripts. Defense-in-depth before anything goes live: (1) a **deterministic, LLM-free static gate** on every script — destructive commands, credential/sensitive paths, network egress, non-Python, >4KB, syntax errors — that runs even on the auto-approve path (comment credits the pattern to Hermes' `guard_agent_created`, a third internal sibling); (2) an advisory Haiku review as a softer layer; (3) staged approval default-ON: candidates land in `auto/.pending/<slug>/` — a dot-dir, so discovery structurally cannot load them — with a dashboard bell for human approval; (4) lifecycle: `.versions/v<N>` snapshots (cap 20) before every overwrite, 30d stale / 90d archive to a restorable-but-never-triggering `.archive/`, global cap 100, entire feature off by default. **For cyril's skill-injection stage:** agent-authored skills must pass a deterministic gate + human approval before entering the injection set, and dot-dir staging is "make illegal states unrepresentable" applied to filesystem discovery — non-live states can't trigger because the iterator can't see them.

### Post-survey case study: Code Review Sage's model display lies (2026-08-04)

Traced after a user sighting of "reviewing with fable" in the Sage app, combined with our wire probe proving fable is neither advertised nor accepted on the v2 switch path for this account (`probe-v2-model-fable-2.16.0.py`). The chain, all verified in source:

1. Sage's settings dropdown is populated from the **static** `model_registry.display_list()` — canonical names like `fable-5-1m`, "NOT the provider ids" (`backend/routes.py:496-510`) — regardless of backend entitlement.
2. The chosen value persists to `config.json review.model` and is consumed in exactly two places: the dashboard display (`reviewer_info()`, whose docstring claims "the model it actually runs") and the **effort-overlay key** `chat.modelDefaults["fable-5-1m"]` — which kiro-cli can never match (its ids are `claude-*`), so the effort overlay is **silently inert** whenever a canonical name is configured.
3. The review session never receives the model at all: `create_session(agent=None)` inherits the runtime's `--agent code-review-sage-reviewer`; no `session/set_model` is sent, no registry translation to the acp id happens, nothing verifies the served model (`review_pool.py:454`).

Net: the UI displays configured-not-served; the review runs on the agent JSON's model (or `auto`). **Confirmed empirically on this host (2026-08-04):** the Issue-Radar-triggered Sage review of `dwalleck/tethys#40` served on `claude-opus-4.6` (sidecar records it in three fields) while the UI said fable; across all 470 sidecars on the machine, no fable id has ever served. Four layers disagreed at once: display (fable) ≠ crew config (empty) ≠ fallback agent pin (`kirocrew.json` → claude-opus-4.8) ≠ served (claude-opus-4.6). This is the survey's own "silently-lying defaults / advisory manifest" antipattern shipping in AWS's flagship app — and the sharpest possible argument for cyril's rule: **displayed model/effort must derive from the wire (sidecar `model_id`, `CommandExecuted` response data), never from configuration.** cyril already conforms (model extraction reads the execute response's `data.model`, which rejections omit).

## The strategic lesson

KiroCrew is AWS's own production proof that **cyril's proxy-stage thesis is correct**: every feature that matters — simulated system prompts, persistent memory, org permission policy, skill loading, MCP virtualization, rewind/regenerate/fork, N-session multiplexing — was built **client-side over plain ACP with zero agent cooperation**, and nearly all of it is vendor-neutral by construction. The moat is not the frontend; it is ownership of the client side of the wire. And the wire is far meaner than the spec — silent ignores, id collisions, turns that end without a response, model-authored strings masquerading as identity. KiroCrew survived it through one discipline worth adopting wholesale: **treat every undocumented behavior as load-bearing and pin it with a live test against the shipped binary**, so a kiro release that changes a quirk breaks a test instead of a user. cyril should stop thinking of itself as a TUI that might grow stages, and start thinking of itself as the stage runtime that happens to ship a great TUI.
