## Overview

On KAS, model/effort/mode live in session configOptions instead of advertised `kiro.dev` commands. This design adds three KAS-only builtin commands (`/model`, `/effort`, `/mode`) registered through a new engine-resolved `ConfigCommandSource`, driven by a `KasConfigSnapshot` — the latest `config_option_update` catalog, extended to carry per-option labels, descriptions, and `_meta.kiro` effort metadata. Commands return a new `CommandResultKind::ShowConfigPicker` intent; the App opens the existing picker overlay under a new `PickerKind::Config` whose confirm sends `BridgeCommand::SetConfigOption`. The `/model` flow chains a second effort picker when the chosen model carries effort levels. All displayed state (toolbar chips and confirmation messages) is read back from the returned catalog's `currentValue` — never from the requested value — because KAS silently ignores invalid effort levels and coerces unknown modes. v2 is untouched: no builtins register, the agent-advertised `kiro.dev` path keeps the names.

## Key decisions

### 1. Engine gating lives in registry construction, not dispatch

A new `ConfigCommandSource` enum (`commands/mod.rs`, beside `HooksCommandSource`) resolved once at startup from the bound `AgentEngine`:

- `ConfigCommandSource::resolve(AgentEngine::Kas)` → `Kas` → `with_builtin_sources` registers `builtin::ModelCommand`, `EffortCommand`, `ModeCommand` and pushes their names into the `/help` snapshot **before** `HelpCommand` is built (the existing eager-copy trap, commands/mod.rs review finding 2).
- `resolve(AgentEngine::V2)` → `Agent` → nothing registers. v2's advertised `model`/`mode` commands arrive via `CommandsUpdated` and register as `AgentCommand`s exactly as today; `session/set_config_option` is "Method not found" on v2, so a builtin would be dead weight, and registering one would shadow the agent's command (`register_agent_commands` skips taken names).

Alternatives considered: (a) engine in `CommandContext`, commands branch at execute time — rejected: `/thinking` derives its lever from the snapshot precisely to avoid engine matching, but model/mode differ structurally per engine (different wire method, different option source, different picker semantics); a per-execute branch would leave a dead KAS path invocable on v2 with no options to validate against, and would shadow the v2 agent commands at registration time anyway. (b) register-on-`CommandsUpdated` — rejected: registration would depend on notification timing and re-registration on every session. Startup resolution matches the three existing sources.

The `AgentEngine` value is already plumbed to `App::new` (`app.rs:416-420`); main.rs passes it to `ConfigCommandSource::resolve` alongside the existing sources.

### 2. The two-step flow is two sequential picker opens, the second gated on the model ack

The picker overlay stays single-shot. Amended in place 2026-10-17 (review round 4, F9/F10/F11/F15 — the Repeated product-repair stop): rounds 1–3 each repaired the pre-ack chain (F1 revalidation source, F6 standalone-vs-chained, F8 failed model set). The class-wide correction replaces it: **no effort step exists until KAS acknowledges the model switch**, so an `effortLevel` set can never precede the model set it belongs to, and the pre-ack exception, the UI-side pending slot and the close-on-failure path are deleted rather than relocated. Decision data lives in components; the App only routes:

1. `/model` (KAS) validates preconditions (active session; snapshot present with a `model` option) and returns `CommandResultKind::ShowConfigPicker { config_id: "model", title, options }`. Options are built by a `KasConfigSnapshot` helper in cyril-core: one `CommandOption` per offered model — `label` = wire `name`, `value` = wire `value`, `description` = wire `description`, `is_current` = (`currentValue` == value), `group` = `None` (credit-rate badges are cyril-lxuo, out of scope).
2. App opens it via `UiState::show_config_picker(ConfigPicker)`, which constructs `PickerState { kind: PickerKind::Config(target), … }` — the target (`ConfigTarget::{Model, Mode, Effort { model_id }}`) is the dispatch key and carries the effort picker's model, so no "Some iff" field exists. `is_current` is honored as sent (no `active_option_value` join — that join exists only for v2 agent titles).
3. On Enter with `PickerKind::Config(target)`, App: (a) **revalidates** via `KasConfigSnapshot::accepts(&target, value)` against the *latest* snapshot in `SessionController` (the picker holds a point-in-time copy; options may have been rebuilt while it was open — a vanished value is refused with a system message, never sent, because KAS accepts garbage silently). The rule is per target: `Model`/`Mode` rows come from the catalog option, so membership in that option's values; `Effort { model_id }` rows come from that model's `_meta.kiro` `EffortMetadata.levels`, so the level must be one of them **and** `model_id` must be the latest snapshot's current model (round 2, F6); (b) sends the `KasConfigRequest`'s `BridgeCommand::SetConfigOption` and records the request with `SessionController::note_config_set_requested` after a successful send (round 1, F4).
4. **Chain on the read-back.** When the `ConfigOptionSet` for a pending `Model` request arrives, `SessionController` consumes the request and — when the rebuilt catalog's current model is the requested one and it carries effort metadata — prepares the effort `ConfigPicker` from that rebuilt catalog (cyril-838u: levels re-derived from the response, never pre-switch data). The App takes it after routing and opens it unless another modal overlay is already up (a picker that opens itself over the user's next action is worse than none; the toolbar already shows the applied default). A failed or ignored model set (returned current ≠ requested) opens nothing. C13 showed post-switch catalogs DO carry an `effortLevel` select option (the round-1 inference from the bogus-model sweep was wrong — F20); its `currentValue` drives the tick (F19, decision 2a below).

Esc on the effort step cancels only that step: the model set was already dispatched, and KAS applies the model's `defaultEffortLevel` itself (confirmed live: the `effortLevel` option appears post-switch at the default). No synthetic `effortLevel` set is sent for an Esc or for a `hasEffort:false` model — sending the default would be a redundant write whose read-back cyril would then have to explain.

`/effort` standalone: reads the **current** model from the snapshot's `model.currentValue`, looks up that model's effort metadata, and opens the same effort picker.

**2a. Effort tick (amended 2026-10-17, review round 4, F19):** effort rows tick the `effortLevel` option's `currentValue` — the level in use — when the model is current and that value is one of its levels; otherwise the model's `defaultEffortLevel`. The chained step is built post-ack, where KAS has just applied the default, so it still reads "default marked" (C8); standalone `/effort` shows what is actually set (C5). When the current model has no effort metadata (`auto`, `hasEffort:false`) the command answers: `"The current model (<id>) has no effort levels — /effort applies to models with effort support."` and sends nothing (the wire confirms no `effortLevel` option exists then; offering one would be offering a silent no-op). When there is no snapshot yet, the "not reported yet" message (§5) applies.

`/mode`: picker over the `mode` option's values (label/description from the wire), same confirm path. No arg form is added for any of the three commands — the acceptance criteria are picker-shaped, and an arg form would need its own validation story; args are answered with a usage line.

### 3. Validation is client-side at three points; the server is never trusted

- **Option presence**: the command refuses when the snapshot lacks the option (model/mode) or the current model lacks effort metadata (effort) — sending an unvalidated `set_config_option` is how you get KAS's silent-accept-then-fail-at-next-prompt behavior (the cyril-fj6j twin).
- **Membership at confirm**: the picker only offers listed values, so an out-of-list value is unrepresentable at open time; the confirm-time revalidation (§2, step 3a) closes the stale-picker race. The model-id check is exact string equality against the snapshot's offered values.
- **Read-back after set**: the shown value is always the returned catalog's `currentValue` from `ConfigOptionSet` (and any later `ConfigOptionsUpdated`), never the requested value. UiState's arm is extended so a `ConfigOptionSet` for `model` / `effortLevel` / `mode` also posts a confirmation built from the returned `currentValue` (e.g. `Model set to claude-sonnet-5.`), mirroring the existing thinking-ack pattern at `state.rs:1031-1043`. The bogus-effort case (SUCCESS, `currentValue` unchanged) therefore *shows* the unchanged value — the read-back is the falsification surface.

### 4. Effort re-derive on model switch (cyril-838u, absorbed)

The invariant has one owner per state machine:

- **UiState**: the existing `set_current_model` clear (`state.rs:1606-1612`) already drops `effort` on any real model change; this design feeds it the KAS model value (already wired at `state.rs:1025-1029`) and adds the repopulation: when the same or a later catalog carries an `effortLevel` option, `effort` becomes `EffortLevel::from_wire(currentValue)`. Ordering within one frame is model-first-then-effort; a frame that changes the model without an `effortLevel` option leaves effort cleared (auto), and the next frame that carries it repopulates — old levels never survive a switch.
- **SessionController / KasConfigSnapshot**: wholesale catalog replacement per notification (never a merge — the catalog is always rebuilt complete, same discipline as `HooksChanged`/`PowersChanged`), so a model switch replaces the offered model list, the current value, and the effort metadata atomically. There is no carried-over `effortLevel` field to leak.

### 5. Timing: options may arrive after session/new — the command says so

`session/new` may omit `configOptions`; the `model` option reliably arrives in a later `config_option_update` (frame 24). The snapshot is `None` until the first catalog lands (`SessionCreated` and `BridgeDisconnected` reset it). `/model`, `/effort`, `/mode` with no snapshot (or no session) answer, in order: no session → the shared `ErrorKind::NoSession` (same as `/thinking`, `AgentCommand`); session but no catalog yet → `"Model options haven't been reported yet — they arrive just after session start; try again."` (command-named per command). A picker with zero options is never opened. This mirrors `PowersCommand`'s "not reported yet" discipline: an empty affordance must say why, not fake a list.

### 6. Per-model `_meta.kiro` effort metadata lives in the extended `ConfigOption` domain types

`crates/cyril-core/src/types/command.rs`:

- `ConfigOption.options: Vec<String>` → `Vec<ConfigOptionValue>`, where `ConfigOptionValue { value: String, name: String, description: Option<String>, effort: Option<EffortMetadata> }`. `name`/`description` are engine-neutral ACP fields; `effort` is `Some` only when the KAS `_meta.kiro` block carried a usable effort spec.
- `EffortMetadata { levels: Vec<String>, default_level: Option<String> }`, constructed only with non-empty `levels` (`has_effort` is derived, never a stored flag — the wire's `hasEffort:true` + missing/empty `effortLevels` is warned and treated as no-effort rather than trusting the flag). A `defaultEffortLevel` not present in `levels` is warned and dropped to `None` (picker then marks nothing as current — no sentinel).

Conversion (`crates/cyril-core/src/protocol/convert/mod.rs` `to_config_options`, :77-99): keeps the generic parts generic — `value`, `name`, `description` map straight from `SessionConfigSelectOption`; the `_meta.kiro` effort block is parsed by a new helper in `convert/kas.rs` (KAS quirks live in the KAS converter, per the conversion-boundary rule; `to_config_options` already delegates Kiro deviations this way — `session_created_from_response` → `kiro::parse_model_catalog`). Malformed `_meta.kiro` (wrong-typed `effortLevels`, non-string entries) warns and yields `effort: None` — never a parse failure of the whole catalog, never a guess.

Downstream type churn from `Vec<String>` → `Vec<ConfigOptionValue>`: `ThinkingState::from_config_options` (uses `key`/`value` only — untouched), the UiState/SessionController arms (use `key`/`value` — untouched), plus test fixtures in `command.rs`, `test_support.rs`, `session_configuration.rs` (updated to the new shape).

### Supporting types and seams (summary)

- `KasConfigSnapshot` (`crates/cyril-core/src/types/command.rs` or a new `types/kas_config.rs`): wraps `Vec<ConfigOption>` with `apply_notification`-free, explicit `replace` semantics plus pure query helpers: `option(config_id)`, `current_value(config_id)`, `picker_options(config_id) -> Option<Vec<CommandOption>>`, `effort_for_model(model_id) -> Option<&EffortMetadata>`, `contains_value(config_id, value) -> bool` (confirm-time revalidation), `current_model()`. Const ids `MODEL_CONFIG_ID = "model"`, `MODE_CONFIG_ID = "mode"`, `EFFORT_CONFIG_ID = "effortLevel"` beside `THINKING_CONFIG_ID`.
- `SessionController` gains `config_options: Option<KasConfigSnapshot>` — replaced on `ConfigOptionsUpdated`/`ConfigOptionSet`, `None` on `SessionCreated`/`BridgeDisconnected`; accessor `config_options()`. (`Option`, not an empty snapshot: "not reported yet" and "reported empty" are different facts — the PowersCommand precedent.)
- Config vocabulary (amended 2026-10-17, review round 4, F11/F13/F14): `KasConfigId::{Model, Mode, Effort}` (wire id, `from_wire`, noun) replaces the string consts; `ConfigTarget::{Model, Mode, Effort { model_id }}` is what a picker sets; `ConfigPicker { target, options }` is one open-able picker; `KasConfigRequest { id, value }` is one dispatched set. `KasConfigSnapshot::picker(target)` builds rows and `accepts(&target, value)` revalidates. `SessionController` owns the pending `KasConfigRequest` and the post-ack effort chain (`note_config_set_requested`, `take_effort_chain`).
- `CommandResultKind::ShowConfigPicker(ConfigPicker)` — domain types only, same carry-the-data pattern as `ShowPowers`.
- `PickerKind::Config(ConfigTarget)` (traits.rs); `picker_confirm` returns `PickerConfirmation { kind, title, value }`, so the App dispatches on the target rather than overloading the display title (the v2 Agent path keeps using `title` as the command name). `Overlay::ALL`, `topmost_overlay`, key dispatch, scroll/paste guards: unchanged — it is the same picker overlay.
- UiState adds `show_config_picker(...)`; the `ConfigOptionsUpdated` arm gains mode and effortLevel handling (§4) and the three confirmation messages (§3). (Amended 2026-10-15, review round 1, F3: UiState does NOT keep its own catalog copy — `SessionController::config_options()` is the sole chain-data source; a UiState copy was implemented, found dead, and removed.)

## Non-goals and future work

- **cyril-838u** (never carry effortLevel across a model switch) — **absorbed**: C9 is its acceptance contract; close as covered when this ships.
- **cyril-cxwb** (lift config_options from session/new response) — stays open, out of scope. Note: the mediator already converts `session/new`-carried `configOptions` into `ConfigOptionsUpdated` (`domain_mediator/commands/session.rs:82-86, 180-186`), so a session/new that *does* carry them flows through this design unchanged; the ticket's contract sources options from `config_option_update` regardless.
- **cyril-lxuo** (per-model effort/credit badges in the picker) — stays open. `rateMultiplier`/`rateUnit` are parsed nowhere in this design; `CommandOption.group` stays `None`. Default-effort marking (in scope) is not a badge.
- **cyril-v2ol** (sticky-default side effect surfacing) — stays open.
- Not in scope: arg forms (`/model <id>`), changing `autopilot`/`memoryReflection`/`contentCollection` (same machinery could serve them later), KAS `session/set_mode` (redundant with `set_config_option mode`), v2 changes of any kind.

## Assumptions (minor; none blocking)

1. `/effort` on a non-effort model **refuses with a message** rather than opening an empty picker or sending a probe set — the wire shows the set would be a silent no-op.
2. Esc on the effort step leaves the model change in effect (KAS applies the default) — matches the "effort merged into the model choice" wire model.
3. Re-selecting the already-current model is allowed and re-sends the set (harmless, and the effort chain doubles as an effort-change affordance).
4. Confirmation messages name the raw `currentValue` (e.g. `claude-sonnet-5.5`), not the display label — the value is what the read-back contract is about.
