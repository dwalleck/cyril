## Slice 3: Fence all six cancel-recovery lifecycles

**Claim IDs:** C4, C5

**Expected behavior:** Each named 2.16.2 and 2.18.1 capture is unwrapped to its recorded JSON-RPC frames, converted through the production KAS adapter, and applied to a fresh `UiState`. At the initial, middle, and terminal checkpoints, one captured identifier owns one committed message. Guarded fields retain the initial snapshot when omitted. After `failed` then cancelled `turn_end`, the committed status is `Failed`, active calls are empty, and activity is `Ready`.

**Oracle:** `.cyril-a5wo/oracle-subagent-interrupt.py` independently groups raw JSON frames by exact `toolCallId`; its `recovery_frames` rows and `.cyril-a5wo/findings.md` record `pending` → `in_progress` → `failed` followed by cancelled `turn_end` in all six captures. Initial raw JSON is the independent expected field snapshot.

**Stress fixture:** Six distinct session/tool-call identities across two engine generations; middle update omits title and kind; terminal update carries empty-string raw output; unrelated metering/context frames surround the lifecycle. Expected: every named capture independently converges to the same state without ID sampling, duplicate commit, field erasure, or stuck activity.

**Regression fence:** `crates/cyril-ui/src/state.rs::cancel_recovery_captures_converge_without_duplicate_or_spinner`, created in this slice, with explicit `CAPTURES.len() == 6`; existing core fences `merge_update_preserves_content_when_update_has_none`, `merge_update_preserves_title_when_update_is_empty`, `merge_update_preserves_raw_input_when_update_has_none`, and `ledger_partial_update_preserves_non_empty_fields`.
