# Design: cyril-s2hb

## Route and inputs

Empirical route: `route.md`, baseline `cc5eba260572e08fd20a58c8b0cdd1aaec782484`, default branch discovered through `origin/HEAD`. Complete observable behavior is `spec.md` Behavior, Success criteria, Decisions and Edge checklist, including its Round7 diagnostics fidelity decisions. No acceptance item is replaced by this design. The Round7 Git/declaration/CLI and capture/launch designs below are released for integrated attempt19 under the parent's delegated approval. P7's driver refinement selects CLI patch production with typed extraction; P9 R9 selects one subprocess Windows lane including explicit batch. No probe receipt or document confers production qualification.

`evidence.md` P1–P4 supplies historical native Linux/Windows comparisons for Python gather/facts, text encoding, diagnostics and Rust raw argument tails; its P5–P6 pending opening state is historical, not the current implementation state. F0 below is retained only as historical spool-mechanism evidence, superseded by the selected stream design below; `checkpoint-A2.md` owns A2 qualification of its exact prior source, and `checkpoint-B.md` with `evidence-B.json` own the completed Linux/Windows B runtime, quality and mutation qualification for that same prior source. The oracle remains `.kiro/code-review/crtool.py` plus independently chosen Git/process fixtures. Fixed clock/version adapters belong to verification, never production CLI/environment switches.

This is additive shipping code with functional-equivalence goals: preserve meaningful target/scope behavior, file/symbol/usage ordering, semantic fields/types, source/content, exit taxonomy and diagnostics statuses/limits, while allowing independent serialization and wording. Round7 supersedes the regular-file descriptor tradeoff: streams must preserve every collected byte with explicit capture completeness, Windows must preserve native executable identity, and diagnostics stdin is null. Necessary safe capture/launch dependencies are permitted by spec.md; unsafe code, arbitrary shell wrapping and descendant targeting remain forbidden. One owner per run directory remains a caller precondition.

## Placement

Select concrete `ReviewRun` operations in a leaf crate. `ReviewRun::new(workspace, directory)` owns the workspace/run anchors and package-version fence. Public `gather`, `facts`, and `diagnostics` operations accept this context; neither binary nor App parses run JSON. `ReviewClock` is the sole narrow generic seam: system UTC/monotonic clock and deterministic fixture clock are its two concrete adapters. Cancellation is a cloneable `Arc<AtomicBool>`-backed value, not a generic executor. Methods expose typed results/errors and the operation's stdout bytes; the binary only writes those bytes and maps errors to exit 2/3.

Public contract for implementation coordination:
- `ReviewRun::new(workspace: impl Into<PathBuf>, directory: impl Into<PathBuf>) -> Result<Self>`; accessors return `&Path` and no JSON representation.
- `gather(run: &ReviewRun, target: &str, scope: &str, clock: &dyn ReviewClock) -> Result<StepOutput>`; `facts(run: &ReviewRun) -> Result<StepOutput>`.
- A2 exposes `ReviewClock::gathered_at_utc() -> Result<String>`; B adds `ReviewClock::diagnostics_elapsed(started: Instant) -> Duration` with its actual consumer. `SystemReviewClock` supplies actual time, fixture implementation supplies fixed values. Returned UTC text is a value seam, not a CLI override. This staged availability follows the no-diagnostics-declaration-before-B partition under delegated Gilfoyle approval; the final contract is unchanged.
- `StepOutput` exposes `stdout() -> &[u8]`; `ReviewError` exposes `exit_code() -> i32`, with context-bearing thiserror variants and no external ACP types.
- `async diagnostics(run, command, options, cancel, clock: &(dyn ReviewClock + Sync)) -> Result<DiagnosticsResult>`; `DiagnosticsOptions` carries timeout; `DiagnosticsResult` exposes the orthogonal typed outcome (Clean/Failed/TimedOut/Cancelled), whether started, `capture_complete() -> Option<bool>` (`None` before launch, `Some` after), and `StepOutput`. The `Sync` clock bound lets the returned future run on the App's existing Tokio runtime without changing the synchronous `gather` clock contract, and no runtime is constructed. `Cancellation::cancel/is_cancelled` operates on one atomic signal. CannotStart, parse, storage, read/setup and lifecycle failures remain typed errors; only the drain deadline expiring before EOF is accepted as an incomplete capture. A started child keeps the one-second direct reap decision deadline plus a final drain of at most one second after its terminal state.
- Crate-private run I/O methods load a validated semantic manifest and atomically replace it; the run owner defines the private required-field schema and preserves unknown later-step metadata. Concrete Git operations remain in `git.rs`: native git2 discovery/revisions/dirty/whole-target document deltas, ONE profiled CLI patch-production operation for all caller scopes, typed `Diff::from_buffer`/`Patch` paths/statuses/statistics/hunks/per-file extraction, and explicit `git grep`. Facts owns source-analysis and rendering policy. Diagnostics consumes shared run/Git boundaries rather than duplicating stamp/serialization behavior. No public manifest representation is exposed.
- `cyril_core::review::{ShellDialect, CrtoolPrefix}` owns safe prefix construction. Existing `HostShell` maps its resolved kind to the small dialect enum; `BridgeHandle::review_shell()` exposes `Option<ShellDialect>` without changing bridge sender/split interfaces. The later App captures it before splitting the handle. No second resolver/config parse.

Forbidden: no leaf import of core/ACP, no library-created Tokio runtime, no second Git implementation or generic Git backend trait, no process abstractions with hypothetical adapters, no JSON parsing in main/App, no diagnostics CLI, no arbitrary shell or descendant killer, no public manifest internals, no duplicate shell resolver. The binary's clap definitions/dispatch live in `crates/cyril/src/crtool.rs`, not main.

## Module shape

Counting convention: physical raw-file production-region lines including comments/whitespace and existing cfg-test helper methods; exclude the terminal top-level `#[cfg(test)] mod tests` body. Counts come from actual source formatted with pinned rustfmt, not declaration-expanded `read` rendering. Baseline census: main 304 production/376 total, core lib 19/19, bridge 417/502, HostShell 478/1036. Python oracle 1070 total; gather/facts/diagnostics is the first 443 lines. Existing callers: CLI main starts bridge/App; bridge resolves HostShell and passes it to mediator; Python experiment driver invokes oracle steps. Existing adapters: system host plus HostShell FakeHost; Python/std process probes.

Alternatives considered for the new run seam:
1. **Selected — concrete run context and three coarse operations.** Caller `gather(&run, target, scope, &clock)` knows anchors and operation inputs, not files or Git/JSON details. Hidden implementation is run I/O, Git, facts and diagnostics. Deep, local ownership; two clock adapters are real. No backend trait.
2. **Command-object executor.** Caller constructs `ReviewCommand::Gather { ... }` and `execute(command, environment)`. One dispatch entry but a widening command/result sum couples every downstream step and adds a second dispatcher beside clap. Test surface moves to generic dispatch instead of actual operations. Rejected.
3. **Injected filesystem/process backend.** Caller builds `ReviewEngine<Git, Fs, Process, Clock>`. Flexible fake backends, but only one shipping adapter per infrastructure trait; tests risk verifying mock echoes instead of Git/native behavior. Rejected.

Capture selection (R7-F02/F08/F10/F18): blocking reader threads fail bounded ownership with inherited holders; process-tree killing stays forbidden; append-mode regular files lose earlier bytes. Selected: Unix Tokio process streams; ONE Windows subprocess1.2.1 `Job` lane for ordinary executables and explicit batch, with `Redirection::Pipe` parent ends converted to Tokio `RecvPipeStream<Bytes>` via `OwnedHandle::from(File)` (interprocess2.4.3). No manual pipe names/create/connect, std-batch adapter, fallback or caller shell wrapper. Evidence.md P8/P9 owns R4 and R9 receipts and their limits; R8's proved std alternative is not selected. The launched job must detach before being returned unreaped, independent starts serialize the synchronous subprocess mark/create/close window, and post-spawn conversion/read failures are typed lifecycle errors rather than CannotStart. No reader thread, unbounded terminal drain or silent output cap is introduced. Concurrent captures and the complete error taxonomy remain production qualification obligations. Prefix placement is unchanged: the small core dialect/prefix module retains resolution ownership without exposing HostShell or duplicating formatting in main.

**Capture privacy:** prior mode0600 and file-unlink receipts prove only the superseded spool implementation. The selected stream handles carry explicit ownership/inheritance with native closure proof still required at the checkpoint; R4 observed unchanged handle/thread residue at1.6s/3.1s while the holder's late write failed, but resource-release/closure proof remains a C7 qualification obligation. Persistent run-artifact permissions and universal Windows ACL hardening remain non-goals.


Deletion/interface/locality tests: deleting run I/O moves validation/atomic/encoding complexity into every operation; deleting facts moves regex/usage/page policy into gather; deleting diagnostics moves command/cancellation/capture state into App; deleting prefix moves unsafe quoting into App. Consumer proof enters public operations. Private page/terminal helpers retain deterministic behavioral fences. Each OS capture/launch adapter hides a real ownership constraint, not a hypothetical backend. The clock retains two actual adapters; concrete process APIs are selected (Unix Tokio streams; one Windows subprocess+interprocess lane including explicit batch), with integrated/native production qualification still required.
