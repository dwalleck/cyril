# Design: cyril-s2hb

## Route and inputs

Empirical route: `route.md`, baseline `cc5eba260572e08fd20a58c8b0cdd1aaec782484`, default branch discovered through `origin/HEAD`. Complete observable behavior is `spec.md` Behavior, Success criteria, Decisions and Edge checklist, including its Round7 diagnostics fidelity decisions. No acceptance item is replaced by this design. The affected capture/launch mechanism selection is PENDING — design owner, with primary-source/native proof before implementation.

`evidence.md` P1–P4 supplies historical native Linux/Windows comparisons for Python gather/facts, text encoding, diagnostics and Rust raw argument tails; its P5–P6 pending opening state is historical, not the current implementation state. F0 below supplies native mechanism evidence for inherited capture-file handles. `checkpoint-A2.md` owns A2 qualification; `checkpoint-B.md` and `evidence-B.json` own completed Linux/Windows B runtime, quality and mutation qualification. The oracle remains `.kiro/code-review/crtool.py` plus independently chosen Git/process fixtures. Fixed clock/version adapters belong to verification, never production CLI/environment switches.

This is additive shipping code with functional-equivalence goals: preserve meaningful target/scope behavior, file/symbol/usage ordering, semantic fields/types, source/content, exit taxonomy and diagnostics statuses/limits, while allowing independent serialization and wording. Round7 supersedes the regular-file descriptor tradeoff: streams must preserve prior bytes, Windows must preserve native executable identity, and diagnostics stdin is null. Necessary safe capture/launch dependencies are permitted by spec.md; unsafe code, arbitrary shell wrapping and descendant targeting remain forbidden. One owner per run directory remains a caller precondition.

## Placement

Select concrete `ReviewRun` operations in a leaf crate. `ReviewRun::new(workspace, directory)` owns the workspace/run anchors and package-version fence. Public `gather`, `facts`, and `diagnostics` operations accept this context; neither binary nor App parses run JSON. `ReviewClock` is the sole narrow generic seam: system UTC/monotonic clock and deterministic fixture clock are its two concrete adapters. Cancellation is a cloneable `Arc<AtomicBool>`-backed value, not a generic executor. Methods expose typed results/errors and the operation's stdout bytes; the binary only writes those bytes and maps errors to exit 2/3.

Public contract for implementation coordination:
- `ReviewRun::new(workspace: impl Into<PathBuf>, directory: impl Into<PathBuf>) -> Result<Self>`; accessors return `&Path` and no JSON representation.
- `gather(run: &ReviewRun, target: &str, scope: &str, clock: &dyn ReviewClock) -> Result<StepOutput>`; `facts(run: &ReviewRun) -> Result<StepOutput>`.
- A2 exposes `ReviewClock::gathered_at_utc() -> Result<String>`; B adds `ReviewClock::diagnostics_elapsed(started: Instant) -> Duration` with its actual consumer. `SystemReviewClock` supplies actual time, fixture implementation supplies fixed values. Returned UTC text is a value seam, not a CLI override. This staged availability follows the no-diagnostics-declaration-before-B partition under delegated Gilfoyle approval; the final contract is unchanged.
- `StepOutput` exposes `stdout() -> &[u8]`; `ReviewError` exposes `exit_code() -> i32`, with context-bearing thiserror variants and no external ACP types.
- `diagnostics(run, command, options, cancel, clock) -> Result<DiagnosticsResult>`; `DiagnosticsOptions` carries timeout; `DiagnosticsResult` exposes typed terminal outcome, whether started, and `StepOutput`. `Cancellation::cancel/is_cancelled` operates on one signal. CannotStart, parse, storage, and lifecycle failures remain typed errors, never fake results.
- Crate-private run I/O methods load a validated semantic manifest and atomically replace it; the run owner defines the private required-field schema and preserves unknown later-step metadata. Concrete Git execution and status classification remain in `git.rs`; facts owns source-analysis and rendering policy. Diagnostics consumes the shared run/Git boundaries rather than duplicating stamp/serialization behavior. No public manifest representation is exposed.
- `cyril_core::review::{ShellDialect, CrtoolPrefix}` owns safe prefix construction. Existing `HostShell` maps its resolved kind to the small dialect enum; `BridgeHandle::review_shell()` exposes `Option<ShellDialect>` without changing bridge sender/split interfaces. The later App captures it before splitting the handle. No second resolver/config parse.

Forbidden: no leaf import of core/ACP/Tokio, no process abstractions with hypothetical adapters, no JSON parsing in main/App, no diagnostics CLI, no arbitrary shell or descendant killer, no public manifest internals, no duplicate shell resolver. The binary's clap definitions/dispatch live in `crates/cyril/src/crtool.rs`, not main.

## Module shape

Counting convention: physical raw-file production-region lines including comments/whitespace and existing cfg-test helper methods; exclude the terminal top-level `#[cfg(test)] mod tests` body. Counts come from actual source formatted with pinned rustfmt, not declaration-expanded `read` rendering. Baseline census: main 304 production/376 total, core lib 19/19, bridge 417/502, HostShell 478/1036. Python oracle 1070 total; gather/facts/diagnostics is the first 443 lines. Existing callers: CLI main starts bridge/App; bridge resolves HostShell and passes it to mediator; Python experiment driver invokes oracle steps. Existing adapters: system host plus HostShell FakeHost; Python/std process probes.

Alternatives considered for the new run seam:
1. **Selected — concrete run context and three coarse operations.** Caller `gather(&run, target, scope, &clock)` knows anchors and operation inputs, not files or Git/JSON details. Hidden implementation is run I/O, Git, facts and diagnostics. Deep, local ownership; two clock adapters are real. No backend trait.
2. **Command-object executor.** Caller constructs `ReviewCommand::Gather { ... }` and `execute(command, environment)`. One dispatch entry but a widening command/result sum couples every downstream step and adds a second dispatcher beside clap. Test surface moves to generic dispatch instead of actual operations. Rejected.
3. **Injected filesystem/process backend.** Caller builds `ReviewEngine<Git, Fs, Process, Clock>`. Flexible fake backends, but only one shipping adapter per infrastructure trait; tests risk verifying mock echoes instead of Git/native behavior. Rejected.

Capture alternatives are reopened by R7-F02: blocking reader threads still fail bounded ownership with inherited holders; process-tree killing remains forbidden; append-mode regular files still lose earlier bytes when reopened with truncation. The requester selected stream preservation, not that loss. Safe nonblocking/available-byte APIs and native handle ownership must be verified before choosing the replacement; no unbounded terminal drain or silent output cap is allowed. Prefix placement is unchanged: the small core dialect/prefix module retains resolution ownership without exposing HostShell or duplicating formatting in main.

**Capture privacy:** prior mode0600 and file-unlink receipts prove only the superseded spool implementation. Replacement stream handles must have explicit ownership/inheritance and native closure proof. Persistent run-artifact permissions and universal Windows ACL hardening remain non-goals.


Deletion/interface/locality tests: deleting run I/O moves validation/atomic/encoding complexity into every operation; deleting facts moves regex/usage/page policy into gather; deleting diagnostics moves command/cancellation/capture state into App; deleting prefix moves unsafe quoting into App. Consumer proof enters the public operations. Private page/terminal helpers retain deterministic behavioral fences. Any replacement OS capture/launch adapter must hide a real platform ownership constraint, not introduce a hypothetical generic backend. The clock remains the existing two-adapter seam; concrete process/handle APIs are pending source qualification.

### C7 verification collection decision

The verification-complexity stop applies to the native inherited-holder qualification failure. The attribution probe observed the product's `Cancelled` receipt and driver exit while both holder and sentinel remained live; the outer Python pipe readers reached EOF only after controlled holder release. The failing observer had conflated driver exit with inherited pipe EOF, not demonstrated product termination of unrelated processes.

The affected verification decision compares three options: change the already-simple direct-child/file-capture product model (rejected: no product defect established); replace the existing real consumer with another lifecycle harness or extend ordinary Rust tests into a duplicate holder protocol (rejected: more fixture/state machinery); or narrow the existing observer to standard-library temporary-file collection and wait for the exact driver process (selected). Only the last option removes the observer's EOF dependency without changing the compiled consumer, fixture topology, oracle meaning, or product.

This technical correction remains under the standing Gilfoyle delegation and C7's existing obligation; no risk, scope, architecture, timeout, size or acceptance waiver is taken. All direct-child, still-live holder/sentinel, fresh challenge, literal stream/artifact, late-write and cleanup assertions remain. The ordinary `diagnostics_call` path has no inherited-holder inputs and need not acquire a new collection abstraction. The affected lifecycle matrix and renewed direct-child-kill mutation are qualified on native Linux/Windows; unaffected command/report/reference evidence remains applicable. `checkpoint-B.md` and `evidence-B.json` own results and provenance; final assembled qualification remains pending.
