# Design: cyril-s2hb

## Route and inputs

Empirical route: `route.md`, baseline `cc5eba260572e08fd20a58c8b0cdd1aaec782484`, default branch discovered through `origin/HEAD`. Complete observable behavior is `spec.md` Behavior, Success criteria, Decisions and Edge checklist, including its 2026-09-30 file-backed capture revision. No acceptance item is replaced by this design.

`evidence.md` P1–P4 supplies native Linux/Windows comparisons for Python gather/facts, text encoding, diagnostics and Rust raw argument tails. P5–P6 are correctly unimplemented feature obligations, not empirical PASS claims. F0 below supplies additional native evidence for inherited capture-file handles. The oracle remains `.kiro/code-review/crtool.py` plus independently chosen Git/process fixtures. Fixed clock/version adapters belong to verification, never production CLI/environment switches.

This is additive shipping code but a behavioral port: Python's target/scope grammar, ordering, serialized output, exit taxonomy, diagnostics statuses and limits are carried into C1–C7 rather than assumed preserved. The explicit exception is the approved regular-file versus pipe descriptor tradeoff. No existing production serialization/permission/uniqueness gate is removed. One owner per run directory remains a caller precondition.

## Placement

Select concrete `ReviewRun` operations in a leaf crate. `ReviewRun::new(workspace, directory)` owns the workspace/run anchors and package-version fence. Public `gather`, `facts`, and `diagnostics` operations accept this context; neither binary nor App parses run JSON. `ReviewClock` is the sole narrow generic seam: system UTC/monotonic clock and deterministic fixture clock are its two concrete adapters. Cancellation is a cloneable `Arc<AtomicBool>`-backed value, not a generic executor. Methods expose typed results/errors and the operation's stdout bytes; the binary only writes those bytes and maps errors to exit 2/3.

Public contract for implementation coordination:
- `ReviewRun::new(workspace: impl Into<PathBuf>, directory: impl Into<PathBuf>) -> Result<Self>`; accessors return `&Path` and no JSON representation.
- `gather(run: &ReviewRun, target: &str, scope: &str, clock: &dyn ReviewClock) -> Result<StepOutput>`; `facts(run: &ReviewRun) -> Result<StepOutput>`.
- `ReviewClock::gathered_at_utc() -> Result<String>` and `ReviewClock::diagnostics_elapsed(started: Instant) -> Duration`; `SystemReviewClock` supplies actual time, fixture implementation supplies fixed values. Returned UTC text is a value seam, not a CLI override.
- `StepOutput` exposes `stdout() -> &[u8]`; `ReviewError` exposes `exit_code() -> i32`, with context-bearing thiserror variants and no external ACP types.
- `diagnostics(run, command, options, cancel, clock) -> Result<DiagnosticsResult>`; `DiagnosticsOptions` carries timeout; `DiagnosticsResult` exposes typed terminal outcome, whether started, and `StepOutput`. `Cancellation::cancel/is_cancelled` operates on one signal. CannotStart, parse, storage, and lifecycle failures remain typed errors, never fake results.
- Crate-private run I/O methods load a validated insertion-ordered manifest, atomically replace it, read/write host text, run explicit Git argv, and build `StepOutput`. Diagnostics consumes these methods rather than duplicating stamp/serialization behavior.
- `cyril_core::review::{ShellDialect, CrtoolPrefix}` owns safe prefix construction. Existing `HostShell` maps its resolved kind to the small dialect enum; `BridgeHandle::review_shell()` exposes `Option<ShellDialect>` without changing bridge sender/split interfaces. The later App captures it before splitting the handle. No second resolver/config parse.

Forbidden: no leaf import of core/ACP/Tokio, no process abstractions with hypothetical adapters, no JSON parsing in main/App, no diagnostics CLI, no arbitrary shell or descendant killer, no public manifest internals, no duplicate shell resolver. The binary's clap definitions/dispatch live in `crates/cyril/src/crtool.rs`, not main.

## Module shape

Counting convention: physical production-region lines including comments/whitespace and existing cfg-test helper methods; exclude the terminal top-level `#[cfg(test)] mod tests` body. Baseline census: main 304 production/376 total, core lib 19/19, bridge 417/502, HostShell 478/1036. Python oracle 1070 total; gather/facts/diagnostics is the first 443 lines. Existing callers: CLI main starts bridge/App; bridge resolves HostShell and passes it to mediator; Python experiment driver invokes oracle steps. Existing adapters: system host plus HostShell FakeHost; Python/std process probes.

Alternatives considered for the new run seam:
1. **Selected — concrete run context and three coarse operations.** Caller `gather(&run, target, scope, &clock)` knows anchors and operation inputs, not files or Git/JSON details. Hidden implementation is run I/O, Git, facts and diagnostics. Deep, local ownership; two clock adapters are real. No backend trait.
2. **Command-object executor.** Caller constructs `ReviewCommand::Gather { ... }` and `execute(command, environment)`. One dispatch entry but a widening command/result sum couples every downstream step and adds a second dispatcher beside clap. Test surface moves to generic dispatch instead of actual operations. Rejected.
3. **Injected filesystem/process backend.** Caller builds `ReviewEngine<Git, Fs, Process, Clock>`. Flexible fake backends, but only one shipping adapter per infrastructure trait; tests risk verifying mock echoes instead of Git/native behavior. Rejected.

Capture alternatives: blocking reader threads fail bounded ownership with inherited holders; process-tree killing violates direct-child-only scope; selected separate file captures hide lifecycle behind diagnostics and have native F0 proof. Explicit risk: descriptor type/seekability differs from Python pipes. Prefix placement alternatives: main-owned formatting duplicates domain safety; exposing HostShell publicly leaks resolution/launch internals; selected small core dialect/prefix module preserves existing resolution ownership and exposes only what the caller needs.

Deletion/interface/locality tests: deleting run I/O moves version/atomic/encoding complexity into every operation; deleting facts moves regex/usage/page policy into gather; deleting diagnostics moves command/cancellation/capture state into App; deleting prefix moves unsafe quoting into App. Every behavioral test enters those same public operations. Private Git/I/O/formatting modules are concrete helpers, not hypothetical interchangeable backends. The clock is the only trait and has two genuine adapters.

These conflict with the pinned leaf/ownership contract or accepted capture tradeoff.

Intended work has existing verified owners: aggregation cyril-7vrl, final report/assets cyril-m139, consent/auto-target launch/run naming cyril-iowg, settings/preflight/App cancellation ordering cyril-305w, explicit targets cyril-9akg, scope/arguments cyril-93fs, workflow cancellation cyril-4o1u, restart recovery cyril-2ruj, complete native qualification cyril-ild0. This issue does not waive their requirements. Native Kiro authentication is not required by this leaf and remains a human prerequisite for live KAS acceptance.

## Approval

2026-09-30, adopted by the design owner under the requester's verbatim scoped delegation:
> “For each issue based on the order of dependencies, create a worktree, run the gilfoyle skill with the rivets id as the argument, approve all signoffs and recommended decisions until the rivets issue is complete, open a PR for the issue and run a code review on the PR. Loop code reviews until no issues remain”
> “Only auto-approve decisions regarding the gilfoyle skill”

Approved decisions: concrete leaf/run seam, module/protected-parent ledgers, growth tripwires, typed resolved-shell projection, two clock adapters, and falsification obligations. Explicit risk acceptances: regular-file capture rather than pipe-sensitive descriptor equivalence; fixed source-compatible report caps/soft page target; unbounded raw output/storage proportional to supplied input; one run-directory owner; direct-child-only cancellation and fixed one-second reap deadline (no promise for unbounded filesystem I/O). No regression fence is waived. No unavailable-host or destructive-operation authorization is inferred. F0 is PASS; C1–C10 await their named implementation checkpoints. This is delegated approval, not fabricated direct technical signoff by the requester.

Technical specificity recorded 2026-09-30: C3's new stamp error renders strings using JSON escaping without surrounding quotes, and non-strings as compact non-ASCII-escaping JSON, as now pinned by the spec owner. This closes `<found>` ambiguity and preserves the existing one-line obligation; it changes no predecessor Python behavior because the stamp fence is new. C3 fixtures include control-bearing strings and non-string values.

C8 specificity, 2026-09-30: “quote” means the issue's ASCII double quote, not apostrophe. The native PowerShell parser falsifier additionally demonstrated U+201C/U+201D/U+201E break the required quoted form; reject those three only for PowerShell. Preserve apostrophes and non-active typographic characters. The spec owner recorded the exact native observations and this narrow safety extension under the existing delegated approval. C8's matrix and mutation proof cover the dialect-specific branch.
