Explicit adjudication of reconstruction candidates

1. cwd behavior — NOT A MISMATCH; real interface tradeoff. The reconstruction correctly observes that top-level `--cwd` is parsed but hidden dispatch precedes `startup_cwd` (`main.rs:21-23,44-52`) and `crtool` passes `"."` to `ReviewRun::new` (`crtool.rs:30-43`). `ReviewRun` resolves that against the inherited process cwd (`run.rs:59-93`). The approved A2 CLI shape requires hidden early dispatch and supplies no separate hidden workspace option (`design.md:29,36-48`); the only explicit workspace-cwd decision for command execution is in future diagnostics. Thus process-cwd inheritance is the current selected boundary, not a proven failure. The syntactically accepted but irrelevant top-level `--cwd` on a hidden invocation is a usability ambiguity that would need a new design ruling if global hidden-command semantics are desired.

2. Scope tokenization — MATCH, intentional grammar. The design explicitly selects Unicode `split_whitespace`, default dot, no quote-aware grammar, and no deduplication (`design.md:17-18`). Source does exactly that and forwards each token as a separate native Git pathspec (`gather.rs:147-170`). Consequently a quoted shell argument containing spaces is intentionally split inside the scope string; this is an accepted grammar tradeoff, not a defect.

3. Stream flushing — no assumed runtime failure. Production writes current A2 outputs through `StdoutLock::write_all` and diagnostics through unbuffered stderr, then returns before `process::exit` (`crtool.rs:52-64`; `main.rs:46-48`). Every current `StepOutput::from_text` path produces newline-terminated text (`gather.rs:32-38,130-145`; `facts.rs:91-127`), so Rust stdout's line buffer flushes during the write; the lock also leaves scope before `process::exit`. Stable Rust documents that `process::exit` skips remaining stack destructors, stdout is line-buffered/flushes on newline or drop, and stderr is unbuffered: https://doc.rust-lang.org/stable/std/process/fn.exit.html, https://doc.rust-lang.org/stable/std/io/fn.stdout.html, https://doc.rust-lang.org/stable/std/io/fn.stderr.html. The parity driver’s explicit flush (`examples/parity_driver.rs:130-154`) is stronger generic-driver error reporting, not evidence of current production loss. Real tradeoff: if a future operation can return non-newline output, production should explicitly flush and classify flush errors; no such A2 path exists.

4. Private page tests — MATCH, explicitly approved. The latest design specifically replaces the old prose assertion with a Unicode-scalar greedy-packing check through private `write_pages`/`body_characters` while retaining public/reference cases (`design.md:236-239`). Actual test exercises those helpers, exact scalar budget, page boundary, and unchanged content (`facts.rs:451-510,516-537`). Its first-page content assertion would distinguish a chars-to-bytes mutation. This is an intentional narrow white-box fence, not an interface leak.

5. Missing CLI coverage in the reconstruction’s restricted view — the bounded observation is accurate, but repository-wide MISSING is false. Rust leaf integration tests call public operations directly (`tests/evidence.rs:177-216`), while the authoritative verification harness separately invokes the actual Cyril subprocess for ordinary/hidden help, gather under poisoned config and absent terminal/agent conditions, facts, startup-artifact absence, and forbidden diagnostics (`.cyril-s2hb/oracles/parity.py:1263-1344`), as required by `design.md:194-198,240-242`. This establishes source coverage placement only; the harness was not executed here, so no pass or CI claim is made.

Real tradeoffs, separately named

- Hidden commands inherit process cwd; top-level `--cwd` is not a hidden-command workspace override under the approved A2 contract.
- Scope is deliberately whitespace-tokenized, so it cannot express one pathspec containing whitespace and performs no deduplication.
- Production relies on newline-terminated A2 output and std stream semantics rather than explicit flush/error classification; future non-newline operations must revisit this.
- Run/facts/gather remain cohesive larger modules under explicitly raised tripwires rather than exposing intermediate symbol/page/manifest invariants through pass-through modules (`design.md:192-206`).
- Git/filesystem/stdio stay concrete; only the clock is injectable. This deliberately favors real-boundary evidence over mock-backed abstractions (`design.md:54-60`).
- One owner per run directory remains a caller precondition, and JSON replacement uses a fixed sibling temporary path; no concurrent-writer recovery policy is implied (`design.md:9,114`).
- Future-B regular-file capture, command parsing, cancellation, report limits, and lifecycle risks are not adjudicated or accepted by this A2 PASS.
