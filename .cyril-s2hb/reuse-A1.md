## Seven symmetry answers

1. **Errors — symmetric and typed.** Prefix construction preserves OS sources (`review/mod.rs:20-27`, `:45-52`) and returns explicit path/safety/namespace variants (`:28-37`). Host-shell resolver errors retain their existing `InvalidConfig` wrapper/source path (`bridge.rs:313-322`). No error is silently converted to a safe-looking fallback. The only intentional divergence is domain separation: prefix errors do not use the crate-wide `ErrorKind`, because callers need the prefix-specific typed result.

2. **Logging — symmetric with ownership.** `review/mod.rs` has no tracing side effects: it is a pure validation/spelling function and returns a typed error. This matches the existing strict resolver path, which returns `HostShellError`; the only nearby resolver log is the pre-existing relative-PATH cwd warning (`host_shell.rs:83-89`) where the resolver makes a fallback decision. Bridge runtime failures continue to log at the existing thread boundary (`bridge.rs:236-244`), while startup resolver failures remain caller-observable through the returned error. There is no duplicate “log then return” path in the new prefix module.

3. **Fallback — deliberately asymmetric where the contract requires it.** HostShell resolution retains its existing configured/auto fallback matrix (`host_shell.rs:349-453`). Prefix construction has no fallback: `current()` canonicalization failure, non-absolute/non-UTF-8 paths, shell-active characters, and unsupported Windows namespaces return errors (`review/mod.rs:45-69`, `:99-143`). This is correct; general HostShell rendering may escape arbitrary commands (`host_shell.rs:260-345`), but the prefix is not allowed to substitute that behavior.

4. **Caller observability — correct seam, pending consumer.** `BridgeHandle::review_shell()` returns the dialect of the exact shell that was resolved (`bridge.rs:40-44`, assignment at `:217-225`), and `split` was intentionally not widened. README usage requires reading it before split (`README.md:167-172`). Current App/workbench callsites still consume `split` directly (`crates/cyril/src/app.rs:403-405`; `crates/cyril-workbench/src/reviewer.rs:48-51`); the design explicitly assigns later App capture, so this A1 increment has no missing production caller. The observable getter itself lacks a direct regression test (listed below).

5. **Resource discipline — symmetric and bounded.** The new path uses one `current_exe` plus one canonicalization, delegates validation without another resolution, and reserves one output `String` (`review/mod.rs:44-92`). Normal validation does not allocate per character; `PathBuf` copies happen only on error. The bridge stores a small `Copy` `Option<ShellDialect>` and adds no channel/thread/process (`bridge.rs:37-44`, `:148-165`). HostShell remains the owner of the executable and terminal command allocations. No duplicate PATH scan or config/env read was introduced.

6. **Guard parity — feature/platform branches are aligned.** KAS modules remain behind `cfg(feature = "kas")` (`protocol/mod.rs:5-12`); bridge has matching KAS/non-KAS assignment arms (`bridge.rs:217-225`) and the client has matching `ResolvedHostShell` representations (`protocol/client.rs:7-11`). Prefix spelling has matching Windows/non-Windows branches (`review/mod.rs:70-89`, `:115-143`): Windows handles drive/UNC/verbatim namespaces and slash conversion; non-Windows rejects a surviving backslash. Tests mirror the host branches for Windows path forms (`review/mod.rs:318-346`) and Unix non-UTF-8/backslash/native-shell cases (`:294-364`). Dialect selection is input-driven in tests, not `cfg!(windows)`.

7. **Acceptance symmetry — strong prefix matrix, one projection gap.** The new tests cover all four dialect variants (`review/mod.rs:195-209`), spaces/Unicode (`:210-221`), safe apostrophe/typographic characters across all dialects (`:223-249`), PowerShell-only smart quotes (`:250-269`), relative and shell-active hazards (`:270-300`), Unix non-UTF-8 (`:303-316`), Windows verbatim drive/UNC/device forms (`:318-346`), and native POSIX execution (`:347-364`). Existing HostShell tests cover resolution, wire names, arbitrary renderer syntax, raw-command shape, signal behavior, and native exits (`host_shell.rs:570-588`, `:850-1039`). The remaining asymmetry is that no behavioral test asserts the new `ShellKind -> ShellDialect` projection or BridgeHandle getter; the structural oracle checks the exact projection source (`.cyril-s2hb/oracles/check_shape.py:80-99`), but source-shape checking is not a runtime acceptance guard.

## Actual issues / guard disposition

- **No unjustified production duplicate found.** `HostShell::wire_name` and `HostShell::review_shell` are both kind mappings, but the former is a deliberately lossy KAS wire projection and the latter is a typed lossless boundary. `HostShell::command`/`push_quoted` and `CrtoolPrefix` both produce shell source, but their contracts are intentionally opposite: arbitrary-command escaping versus fixed-prefix rejection. The WSL/path normalizers are also not safe-prefix helpers.
- **Actual acceptance guard gap:** add/retain a behavioral fence in the owning test context for all four `HostShell::review_shell` results and the bridge `Option` behavior (KAS resolved shell → `Some`, V2/non-KAS → `None`). `host_shell.rs:570-588` cannot catch a swapped new projection because it tests only `wire_name()`; the shape oracle is useful but is not an independent runtime oracle.
- **Secondary coverage gap, not a production defect:** `CrtoolPrefix::current()` (`review/mod.rs:45-55`) and the `CurrentExecutable`/`Canonicalize` source-bearing variants are not directly exercised. The deterministic matrix exercises `from_executable`, which is the correct seam for fake canonical paths, but a small native call-through check would be needed to guard the public `current` wiring. No safe fault injection for `current_exe`/canonicalize exists in the current design, so this is weaker than the projection gap and should not motivate a second resolver/backend.
- **No missing safety guard in production:** all approved ASCII hazards, controls, surviving Unix backslashes, PowerShell smart quotes, relative/non-UTF-8 paths, and unsupported Windows namespace forms have explicit rejection paths and corresponding matrix evidence. The lack of a fallback is intentional and required.
