## Data and lifecycle semantics

- A KAS status snapshot carries the real wire sessionId. Do not bind the first received session's data to the pending root by guesswork. Latest snapshots for the single admitted new/load transition are staged and promoted only when the successful response supplies the matching ID. The fresh-session reset clears old state before initial matching data is published. Peer/workflow session snapshots cannot contaminate the root panel. caar consumes this already-correct admission/staging lifecycle rather than introducing a parallel guard.
- Replacement snapshot is authoritative: removing a server clears its stale auth notice/selection; a connected row clears its failedAuthorization URL. Removed selection moves to an existing visible row without executing an action on that replacement implicitly.
- Missing accessMode/registry fields stay absent. Known non-registry, registry-filtered, unresolved, disabled and governance-disabled states are not flattened into “not connected”. Unknown reason/state is visible data, never a permissive policy default. Retained policy reconciles only with the current producer's source-proven authoritative contradiction recorded in review-decisions F3; empty/incremental/unknown/foreign metadata is not guessed recovery.
- Preserve exact advertised wire identities: KAS `promptName` is canonical prompt `.name`, while its distinct display `name` reuses optional `.title`. Display labels never become request identity. Opaque server/tool/prompt names and resource URIs are not shell fragments. Input argument values are strings keyed by advertised names; validate required presence through the existing action path before sending. Fetch output is external data: render safely, show nontext kind/MIME/URI metadata, and never execute or implicitly inject it.
- A rejected/malformed read/reset is a visible operation failure distinct from an empty successful content result. No blanket `.ok()` or empty-list fallback. Existing transport closure/fatal-versus-recoverable classification remains intact.
- Status can update while a read/reset is in flight. Keep identity/operation target fixed and reject stale results instead of applying them to a new selected server/session. No new automatic retry behavior.
- Elicitation notices include actual session/tool context and distinguish form versus URL; no requested answer values or synthetic completion are fabricated. Decline is a valid protocol result, not a failed parse or null success. A future interactive policy must replace this approved policy, not coexist as a secretly advertised half-handler.
