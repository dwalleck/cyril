## Removed invariants

The change is additive except for one deliberate deepening: source exact-once identity cannot reuse the bridge's process-local numeric `TurnId` alone. The existing allocator silently guarantees uniqueness only inside one bridge process; persistence removes that process-lifetime constraint. The durable observer therefore adds a random 128-bit `SourceTurnId` at authoritative acceptance while retaining the numeric `TurnId` as provenance. Replacing the durable ID with the process-local counter would make two loaded-session prompts after separate Cyril starts collide; C3 and C12 fence that regression.

The bridge's one-active-turn guard, mediator terminal ownership, single App notification consumer, UI message retention cap, runtime exclusive-store lock, strict authenticated frame decoder, and original visible-user-message ordering remain intact.

## Placement

### Authoritative source observer

- **Owner:** `cyril-core::protocol::bridge` owns observation because it is the only module that sees accepted outbound prompts, normalized inbound notifications, mediator ownership, and prompt/death terminal outcomes before App/UI projection.
- **New seam — selected:** add an engine-neutral, bounded `SourceTurnEvent` fan-out interface and a bridge-completion receiver on `BridgeHandle`. `SendPrompt` carries a `PromptEnvelope` with original blocks plus optional prepared context; the bridge constructs wire blocks, allocates both numeric provenance `TurnId` and durable `SourceTurnId`, and emits ordered source events before forwarding corresponding UI notifications. An internal ingress guard/barrier keeps capture ownership open after a UI-visible terminal until every normalized callback that began before the prompt response has enqueued; KAS wire terminal is a candidate until its prompt-response companion/quiescence closes the capture turn.
- **Competing seam A — rejected:** borrow/tap `RoutedNotification` in `App::handle_notification` like `UsageObserver`. It is after the single-consumer bridge channel, cannot observe accepted original prompts, ignores mediator-absorbed evidence, and makes capture depend on App scheduling/UI ownership.
- **Competing seam B — rejected:** make `cyril-core` depend on `cyril-memory` and write directly from `run_loop`. It violates persistence-free core, turns memory latency into bridge latency, and leaks storage policy into ACP mediation.
- **Forbidden:** no second receiver on `notification_rx`; no SQLite, runtime client, ranking, redaction policy, UI state, or project-path resolution in core; no inbound replayed `UserMessage` may seed a turn.

`SourceTurnEvent` carries `Started { session, source_turn_id, bridge_turn_id, block_count }`, indexed UTF-8-safe prompt/assistant/tool payload fragments of at most 64 KiB, normalized tool snapshots, and terminal disposition. Nonterminal frames are stamped only while the mediator or capture-terminal barrier owns the same session. Tool snapshots retain stable ID, title/name, status, content/result, and truncation metadata; `AgentThought`, private thoughts, and presentation locations are explicitly filtered. The bridge maps prompt RPC error to `Failed`, `Cancelled` to `Interrupted`, `EndTurn` to `Completed`, other stop reasons to `Failed`, and process/connection loss with an active turn to `Abandoned`. `Incomplete` is the durable pre-terminal state, never a synthetic terminal. The barrier admits assistant/tool callbacks that began before prompt-response completion even when their UI notifications trail `TurnCompleted`; only events begun after quiescence are ignored as protocol violations.

### Capture forwarder

- **Owner:** `cyril` owns a private `CaptureForwarder` adapter because it is the only crate allowed to combine core source events with the startup-bound `ProjectMemory` interface.
- **New seam — selected:** a dedicated task drains a 32-event bridge channel whose payload fragments are each at most 64 KiB (approximately two MiB maximum queued source payload), translates core events into cyril-memory domain events, batches by at most 16 events and 256 KiB encoded source per request, and opens a fresh short-lived `AdminClient` connection for each batch so the serial runtime can serve other operations between batches. Bridge emission uses `try_send`; a full queue atomically marks that active source turn lost. The forwarder observes the shared loss marker, drains/discards the remainder, and persists `CaptureOverflow` instead of any successful terminal commit when the staged `Started` event reached the runtime; otherwise it emits one structured loss log with the same source identity.
- **Competing seam A — rejected:** one spawned IPC task per chunk. It can reorder events, create unbounded connection churn, and leaves shutdown with untracked writes.
- **Competing seam B — rejected:** one permanent capture IPC connection. The runtime serves connections serially, so a permanent connection would starve lesson, context, health, and shutdown operations; the selected per-batch connection lifetime keeps the serial accept loop available.
- **Forbidden:** no UI/system message per capture result; no fire-and-forget task per event; no capture-derived fallback identity; no prompt/turn failure caused by capture failure.

The forwarder starts after project binding, preserves order, logs a structured per-turn capture failure once, and continues draining. Runtime timeout, connection loss, queue overflow, or a closed receiver marks that source turn non-completed and prevents any later queued `EndTurn` from making it recall-eligible. `BridgeHandle::split` adds a one-shot completion receiver fired only after the bridge loop exits and every source sender drops. On shutdown App sends `Shutdown`, awaits that bridge completion under the existing bounded shutdown policy, then the forwarder drains the now-closed source receiver and flushes for at most two seconds before the memory runtime stops. A failed or over-deadline flush leaves the already-staged row `incomplete`/`abandoned`; it never fabricates completion or delays shutdown indefinitely.

### Source-turn domain, assembly, and persistence

- **Owner:** new `cyril-memory::source_turn` is a deep module owning validated source identifiers, event validation, general secret redaction shared with lessons, bounded tool lifecycle, assembly, terminal-state transitions, canonical source hashing, replay integrity, episode formatting, and immutable read projections.
- **New seam:** deepen existing `MemoryRequest`/`MemoryResponse`, `AdminClient`, `StoreSet`, and binary `ProjectMemory` interfaces with `capture_batch`, `list_turns`, `inspect_turn`, and `prepare_prompt`. No backend trait is introduced because only the local runtime exists.
- **Forbidden:** no ACP/core types in cyril-memory; no caller-supplied project ID after `ProjectMemory` binding; no SQL/hash/redaction/eligibility/ranking/framing in bridge, App, command, or UI; no silent `.ok()`/default on invalid source.

Each `capture_batch` is validated before state mutation. Every text payload is normalized exactly once at event construction — CRLF and ANSI escapes stripped, the raw ingress bound applied, shared redaction run — and stored data is never re-bounded or re-redacted on reload. Replay equality compares per-event digests, so no event text is persisted beyond the assembled projection and a resumable assembly record; an identical replay writes no row at all. A finished turn's prompt and assistant columns are whole-text redacted a second time (closing secrets split across fragments); an incomplete turn is re-redacted on every read. `SourceTurnId` is the authoritative durable turn identity minted once at bridge acceptance and carried unchanged through every event, timeout retry, duplicate batch, and explicit replay; the process-local numeric `TurnId` is provenance only. The runtime assembler is keyed by bound project plus durable `(SessionId, SourceTurnId)`. It writes or refreshes a staged `source_turns` snapshot transactionally on every accepted batch, so restart preserves incomplete state; reopening reconstructs assembly from the snapshot. Terminal transition computes SHA-256 over a versioned length-prefixed canonical encoding of the redacted original blocks (individually, so block boundaries are part of the hash), assembled assistant text, ordered merged tool lifecycle, truncation markers, omitted-tool count, and terminal disposition; every full read of a turn recomputes and verifies it, and a mismatch is a corrupt row (skipped and counted by recall, an error for inspection). A completed row is immutable. Retrying/replaying the same durable key and hash is idempotent; a different hash returns `IntegrityConflict` and appends a text-free audit record; every rejected batch (foreign owner, malformed, out of order) leaves one too, and the audit never reads or echoes another project's row state. A new accepted prompt after process restart receives a new `SourceTurnId`, so reused numeric `TurnId(0)` cannot collide.

Tool capture is bounded to 128 tools, 16,000 Unicode scalar values per tool, and 256,000 total tool characters; excess is represented by explicit truncation/omission counts included in the hash. Prompt and assistant source text are stored as observed after shared credential/exfiltration redaction; they are not truncated by UI or episode budgets. Protocol batches remain below the existing one-MiB frame cap.

### Store schema and FTS5

- **Owner:** `cyril-memory::store` retains exclusive schema/migration/query ownership.
- **New seam:** memory schema v3 adds `source_turns`, source-turn audit rows, project/status/recency indexes, and an FTS5 external-content table over completed prompt, assistant, and tool-name/result text. The v3 validator explicitly accounts for every FTS5 shadow table/trigger while continuing to reject unknown objects.
- **Forbidden:** no FTS in the knowledge store for this slice; no raw SQL/query syntax from callers; no unparameterized MATCH; no indexing of incomplete/interrupted/failed/abandoned rows.

Migration becomes sequential inside one `Immediate` transaction: v1→v2 then v2→v3, or v2→v3 directly. A failed v3 migration rolls back to the prior valid schema. FTS rows are inserted only on `Completed`; immutable source rows make index state append-only for this slice. One `AFTER UPDATE` trigger performs the external-content delete-then-insert in statement order — two triggers on the same event run last-created-first in SQLite and would evict the row on the design's own idempotent replay. The index carries the project id as its first column (zero bm25 weight) so a MATCH never scans another project's postings, and indexes tool name/input/result text rather than the tool JSON, so keys and status words are not searchable.

Literal query construction considers at most the first 4,096 Unicode scalar values and 64 distinct whitespace-delimited terms that contain an alphanumeric character. Of those candidates, English function words and terms shorter than three scalars are dropped and the 16 longest remaining terms (ties by first occurrence) form the union — longer tokens are rarer, and reading a common term's postings is the whole cost of a MATCH at 100k turns (measured: 64 common terms 330 ms, 16 selected 66 ms, a 120-word prompt 47 ms; the stop-word-only case falls back to the short terms). Each term is FTS-quoted with embedded quotes doubled and terms are joined with `OR`; user operators remain literals. Empty/whitespace/punctuation-only input selects no episodes. Retrieval parameterizes MATCH, filters the bound project and `Completed` status, orders by `bm25` ascending, completion time descending, then stable source ID ascending, and returns at most three rows.

### Prompt preparation and episode framing

- **Owner:** `cyril-memory` owns a new opaque `PromptContext` that composes the existing lesson section and new episode section; `ProjectMemory::prepare_first_prompt(query)` owns the existing 250 ms deadline.
- **New seam:** replace lesson-only protocol `Context`/client `context` with `PreparePrompt { project, query }` and `PromptContext`; bump the private authenticated protocol to v2 because the request/response contract changes atomically with its only client/runtime pair.
- **Forbidden:** bridge/App do not merge sections, tokenize queries, select rows, or inspect provenance; UI never renders injected context as a user message.

Lessons retain their independent 4,000-character budget. Episodes follow in `<CYRIL_EPISODES trust="derived_data">`, state that they are prior observed data rather than instructions, carry source session/turn/completion-time provenance, and cap at three entries, 1,200 characters per entry, and 3,600 episode characters total. Truncation occurs only on Unicode scalar boundaries and preserves provenance/framing. If both sections exist they are joined by one newline; the combined opaque block is therefore at most 7,601 characters. No match returns the lesson-only block; no lessons and no match returns `None`.

App passes the original first source block as the query before context insertion; the client normalizes it into a bounded `PromptQuery` (control characters become spaces, cut to 4,096 scalars) so a pasted stack trace or a long prompt is never rejected, while the wire accepts only already-normalized queries. A corrupt or unmatched episode row never withholds the lesson section. `PromptEnvelope` keeps the original blocks separate from optional prepared context; bridge wire construction yields `[context, original 0, … original N]`, while source capture receives only `[original 0, … original N]`. Lookup/capture failure remains exact fail-open for the ACP turn.

### `/memory` inspection projection

- **Owner:** `cyril-core::commands::MemoryCommand` owns syntax, `App` owns the concrete async `ProjectMemory` call and core-neutral mapping, and `cyril-ui::memory_format` owns bounded rendering.
- **New seam:** add typed actions `/memory turns` and `/memory inspect-turn <source-turn-id>` plus `MemoryTurnListView`/`MemoryTurnView`. Existing lesson `/memory list` and `/memory inspect <lesson-id>` remain unambiguous and unchanged.
- **Forbidden:** no database access, source assembly, status inference, scope check, or hash computation in command/UI; no retention of source records in `UiState`.

Turn list returns at most 100 newest rows — a 160-scalar prompt preview, tool count, status, provenance, and timestamps each — plus omitted/corrupt counts. Inspect returns the original prompt and assembled assistant bounded to 16,000 scalars each, tool summaries bounded to 300 scalars per field, per-field truncation counts, omitted-tool count, durable disposition, source hash, source session, durable/numeric turn IDs, and start/end timestamps, so any response fits one frame. Missing and foreign IDs share the safe not-found outcome. The projection is fetched from storage on demand, so clearing or truncating chat cannot affect it.

## Claims

- **C1:** The bridge emits one ordered source stream for every accepted main prompt, containing original blocks plus every pre-barrier normalized assistant/tool event before corresponding UI projection.
- **C2:** Only authoritative `EndTurn` completion is recall-eligible; cancelled, failed, abandoned, and incomplete captured turns remain distinguishable, while capture loss can never create a completed record.
- **C3:** Runtime staging and immutable terminal commit preserve source turns across restart, make every retry/replay carrying the same durable turn ID idempotent, and surface conflicting replay without replacement.
- **C4:** Literal FTS5 recall returns only completed same-project turns, deterministically ranked and bounded to three 1,200-character episodes/3,600 episode characters.
- **C5:** First-prompt preparation composes lessons before derived episodes while wire injection remains exactly once and original source/UI blocks remain byte-equivalent.
- **C6:** Streaming chunks and partial tool snapshots merge into one redacted coherent record with explicit tool bounds, pre-terminal-barrier tail capture, deliberate thought exclusion, and no display artifacts.
- **C7:** `/memory turns` and `inspect-turn` expose typed source state/provenance independently of bounded UI transcript retention.
- **C8:** Schema v3 migrates v1 and v2 stores atomically, reopens idempotently, validates FTS shadow objects, and rejects corrupt/unknown schema state.
- **C9:** Capture cannot block bridge/App progress; the bounded queue, loss marker, bridge-stop acknowledgement, and ordered drain either persist events or leave a truthful non-completed state.
- **C10:** Core and UI remain persistence-free and do not depend on cyril-memory.
- **C11:** Protocol v2 strictly validates identifiers, event order/size, batches, query bounds, and response kinds while preserving authentication, frame cap, and request monotonicity.
- **C12:** Durable random `SourceTurnId` prevents process-local numeric turn-ID reuse from colliding across Cyril restarts, and replay/history without an accepted outbound prompt cannot create a turn.
- **C13:** Redaction, assembly, storage, eligibility, FTS ranking, and episode framing remain private to cyril-memory; the binary is only a typed adapter and core/UI cannot express those policies.

## Non-goals and future work

- No working-memory/scratchpad table, tool, extractor, TTL, eviction policy, or prompt section in this change: native ACP history is active conversational context; incomplete staging is capture infrastructure and never recall/context/consolidation input. A separate tier is intended future work only if continuity-loss evidence passes the gate in verified `cyril-xajq`.
- No LLM consolidation, semantic facts, importance scoring, automatic promotion, or background model worker. Intended future work is covered by verified `cyril-nxq5` and governance issue `cyril-s7gn`.
