## Behavior

- Install a real URL host-callback adapter on the bound KAS engine. Derive `clientCapabilities._meta.kiro.openExternalUrl:true` from that installation, using the same adapter datum that permits dispatch. v2 and no-KAS builds must neither advertise nor execute it.
- Parse the current request `{url}` in core. Queue a typed, global URL-surfacing event through the existing bounded host/domain path and display a manual sign-in link. Match existing v2 manual-URL behavior; no browser launch, clipboard subprocess, shell command or confirmation framework is introduced.
- Reply `{success:true}` after the URL event is accepted for delivery. This means **handled for display**, not opened, authorized, connected, or OAuth completed. Delivery failure cannot return success. Malformed handled requests produce an explicit parameter error; unsupported engine requests are refused as method-not-found rather than `null` success.
- Preserve the original URL in the typed core event. For presentation, ordinary URL/message characters (including printable quotes, backslashes and Unicode) remain exact; a tiny private streaming UI formatter visibly escapes terminal controls and Unicode bidi controls with `char::escape_debug` only for those characters. The existing App/UI paths have no reusable full-URL escaper; applying `str::escape_debug` to the whole URL would unnecessarily alter printable characters. Never execute it. Do not log or persist OAuth query/fragment data in structured diagnostic records; retain only safe lifecycle metadata there. No speculative URL rewriting/normalization or intermediate escaped-string allocation.
- Convert KAS `session_info_update` `display_error` with `errorType:"mcp_connection_error"` into a typed consumer-visible error carrying the original message and classification. It must remain visible even if an MCP status later updates, and it must not complete/fail a chat turn or fabricate a disconnect. Other `display_error` classifications are not silently claimed by this issue.
- Initial passive OAuth arrives in `mcp/status`, not necessarily this callback. In the integrated stack, the panel shows that URL, explicit authenticate sends reset with `startOAuth:true`, and status—not acknowledgements—clears pending auth and shows connected.
- Keep `secretStorage` absent. Credential persistence is not requested; KAS's supported in-memory OAuth fallback is retained. Do not implement or wait for dark `oauthCompleted` / `oauthCompletion:"notification"` fields absent from the producer.
